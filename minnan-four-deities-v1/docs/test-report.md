## 功能验收

- 首页四个神明卡片同时显示，四张 JPG 人物图均完成加载且 `naturalWidth > 0`。
- 图片与名称逐一对应：妈祖、观音菩萨、关帝爷、玄天上帝。
- 四位神明都能进入同一套请示页面，并正确替换名称、配色与人物插画。
- 问题输入框最大长度为 200 字，可正常输入和编辑。
- 页面资源记录中没有 `/api/` 请求，页面也不读取 Cookie、`localStorage` 或数据库。
- 两枚筊杯由两个独立随机值生成朝向，问题内容和神明选择不参与随机。
- 平面 + 平面得到笑杯；凸面 + 凸面得到阴杯；一平一凸得到圣杯。
- 动画进行期间按钮立即禁用，连续点击不会生成多个结果。
- 动画结束后，最终杯面、结果图示和杯象名称逐项一致。
- 两枚筊杯采用用户提供实物照片中的高阶、不对称月牙轮廓，并保持深酒红木质、厚边和镜面高光。
- 每个问题只能完成一次有效投杯，结果出来后不能对同一问题再次投杯。
- 结果区域只显示杯象名称、两个筊杯图示和“继续请示”，没有朝向解释、吉凶判断或 AI 文本。
- “继续请示”会清空上一问和杯象，并保留当前神明重新进入输入状态。
- 点击“返回四位神明”会结束当前请示并回到首页。
- 桌面 1440px 和手机 390px 视口均无横向溢出，浏览器无未捕获异常。
- 首页直接使用四张完整竖幅人物图，保留完整的竖排名称牌匾；卡片下方不再重复显示名称或配色说明小字。
- 首页使用四张全身像；点击某位神明后，请示页只加载对应的端坐像，四位神明的首页图和端坐图路径分别验证。
- 单张插画请求失败时会显示“画卷暂未展开”占位，人物名称和进入请示的按钮仍然可用。
- 样式表中的类选择器均能在页面结构或运行时脚本中找到对应类名，没有遗留的无效选择器。

## 未覆盖项

- 真实 iPhone Safari 和 Android Chrome 的手机浏览器兼容性需要再用实体设备打开确认；当前自动化覆盖 Edge 桌面与移动视口。
- 人物插画由项目维护者使用 GPT 生成；正式上架前应结合所使用服务的适用条款核对商业使用与再分发要求。它们不是宗教造像或历史考据图。

## Android 真机验收

- 设备：Xiaomi Android 16（API 36）。
- 安装包：`com.minnanfourdeities.app`，版本 `1.1.0`，最低 Android 7.0。
- 关闭 Wi-Fi、移动数据并开启飞行模式后，应用可冷启动。
- 四位神明页面与端坐图均正常切换。
- 两轮“输入问题 → 掷杯 → 查看杯象 → 继续请示”流程通过。
- 同一问题只允许一次掷杯，结果按钮只显示“继续请示”。
- 真机 WebView 未发现 `/api/` 请求、外部资源请求或模型 token 调用。
- 2.7 秒掷杯动画采样 316 帧，平均约 8.55 ms/帧，95% 帧在 8.4 ms 内；仅开场有 1 帧超过 25 ms，未检测到主线程长任务。
